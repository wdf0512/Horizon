## [Mojo Programming Language Now Open Source Under Apache 2 License](https://simonwillison.net/2026/Aug/18/mojo-is-now-open-source/) ⭐️ 8.0/10

The Mojo programming language, initially announced in May 2023, has been released as open source under the Apache 2 license after shipping its version 1.0. This fulfills a long-standing promise and marks the official open-sourcing of its compiler and toolchain. Open sourcing Mojo allows community contributions, accelerates ecosystem development, and makes GPU programming more accessible. It is a significant milestone for a language that aims to be the one language for programming modern heterogeneous computing systems, from CPUs to NPUs. Mojo is a systems language with Python-inspired syntax but is no longer a Python superset; it incorporates features like static typing and a borrow checker from Rust. It builds on MLIR instead of LLVM, enabling efficient compilation for CPUs, GPUs, TPUs, and other accelerators.

rss · Simon Willison · Aug 18, 21:39

**Background**: Mojo was created by Modular Inc. and initially pitched as a superset of Python to simplify AI and high-performance computing. By 2025, the vision shifted to a standalone language optimized for painless GPU programming, using Python-like syntax. It leverages MLIR, a modern compiler framework, to target diverse hardware without requiring deep hardware expertise.

## [Critique Reveals Flawed Evaluation Practices in Sparse Attention and KV Cache Compression Research](https://www.reddit.com/r/MachineLearning/comments/1vqqqcs/how_to_make_any_sparse_attention_kv_compression/) ⭐️ 8.0/10

A researcher with years of experience in the field exposed common tricks that make sparse attention and KV cache compression methods appear deceptively good, such as using synthetic tasks without distractors, contaminated benchmarks, and unhelpful few-shot setups. These practices undermine the reliability of research claims, potentially misleading the community about true progress and hindering the deployment of efficient long-context models in real-world applications. Specific tricks include using Needle-in-a-Haystack with no distractors, exploiting benchmarks the model has already memorized, extensively tuning hyperparameters for one&\#x27;s own method while leaving baselines unchanged, and reporting only aggregated metrics to hide failure cases on tasks like NIAH-MK3 that actually stress-test lossless compression.

reddit · r/MachineLearning · /u/korec1234 · Aug 17, 12:18

**Background**: Sparse attention and KV cache compression are techniques to reduce the memory and compute costs of long-context transformer models. Sparse attention computes attention only over a subset of tokens, while KV cache compression reduces the size of stored key-value tensors. The Needle-in-a-Haystack \(NIAH\) test hides a specific fact in a long irrelevant context to evaluate retrieval ability, but flawed setups can make weak methods appear effective.

## [Diffusion Model Trained on 264KB RAM Microcontroller](https://www.reddit.com/r/MachineLearning/comments/1vrk7t5/trained_an_diffusion_model_that_runs_on_264kb_of/) ⭐️ 7.0/10

A developer trained a diffusion model on a Shrike lite board with only 264KB of SRAM, generating 32x32 pixel images. An attempt to accelerate inference with FPGA-based parallel MAC engines paradoxically slowed generation from ~70 seconds to ~220 seconds due to a memory wall bottleneck. This demonstrates the feasibility of generative AI on extremely resource-constrained edge devices, which could enable new applications like on-device image generation. It also highlights the critical memory wall bottleneck that often limits the benefit of adding parallel compute in embedded systems. The model uses heavy INT8 quantization with 16-bit accumulation for inference on a Shrike lite board \(RP2040 MCU + 1120 LUT FPGA\) with 264KB SRAM. The MCU-only mode took ~70 seconds per 32x32 image, while the FPGA-accelerated version took ~220 seconds, showing that memory I/O dominated over computation.

reddit · r/MachineLearning · /u/PandaBean18 · Aug 18, 09:26

**Background**: Shrike lite is an open-source board combining a Raspberry Pi RP2040 microcontroller and a small FPGA, designed for low-cost embedded experiments. Diffusion models are a class of generative models that produce images by iteratively denoising random patterns. The memory wall refers to the bottleneck where memory bandwidth cannot keep up with compute speed, often making parallel hardware less effective. Quantization reduces the precision of model weights and activations \(e.g., from 32-bit float to 8-bit integer\) to save memory and speed up inference, but can introduce visual artifacts.
